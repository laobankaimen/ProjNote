# ProjNote 项目管理工作台

以单用户离线使用为默认模式的项目工作工具，提供原生桌面便签、浏览器工作台及可选局域网协同。项目、任务、计划版本、需求、工作记录、工时、日志、会议纪要和问题保存在负责人机器，支持搜索、导出及完整备份恢复。当前版本为 **v0.6.1-dev / schema10**。

设计资料仅保留：

- [详细设计方案 V2.1](docs/ProjNote-详细设计方案V2.1.md)：当前架构、数据规则和交互设计。
- [局域网协同最小设计](docs/局域网协同最小设计.md)：已实现的协同范围、权限和证书规则。

按已确认的范围，不再扩展广泛的GJB适配功能。需求管理、计划版本、覆盖检查和导出维护用于日常项目管理；局域网协同默认关闭，由负责人明确开启。

## 启动与退出

Linux 使用 `dist/ProjNote`，Windows 使用 `dist/ProjNote.exe`。正常启动只显示右下角的单箭头便签入口，不自动打开浏览器。点击箭头打开便签，入口随之隐藏；点击面板的 `×` 返回入口并保留草稿。面板底部可直接“打开完整工作台”。入口固定在可见工作区右下角，不支持拖动。

```bash
./dist/ProjNote
./dist/ProjNote --data-dir ./data
./dist/ProjNote --data-dir ./data --browser       # 明确打开完整网页
./dist/ProjNote --data-dir ./data --compact       # 明确展开原生便签
./dist/ProjNote --data-dir ./data --no-browser    # 仅启动服务
./dist/ProjNote --data-dir ./data --no-desktop    # 前台服务，本次不显示便签入口
./dist/ProjNote --data-dir ./data --foreground    # 调试时保持前台，Ctrl+C退出
```

`--browser --no-desktop`只打开浏览器。`--browser`不能与`--compact`或`--no-browser`同时使用；`--compact`不能与`--no-desktop`同时使用。设置中可关闭下次启动时的桌面入口；关闭后不会改为自动打开浏览器。同目录重复启动复用原服务，普通启动不主动展开便签面板。

默认数据目录为程序同级的`data`；该位置不可写时使用用户配置目录。本机负责人服务始终只监听`127.0.0.1`，首选18600端口，冲突时最多顺延99个端口。实际地址见启动输出或数据目录的`runtime.json`。首次为空工作空间，可自行创建项目；示例数据须在设置中明确加载，且只允许空库。

默认启动保持后台服务，关闭便签、浏览器或启动它的终端不结束服务。Linux图形启动确认服务就绪后返回；Windows的`ProjNote.exe`无控制台窗口。使用设置页“退出服务”或以下命令结束；`Ctrl+C`仅结束`--foreground`等前台启动：

```bash
./dist/ProjNote --data-dir ./data --stop
```

登录系统后自动启动可在“设置与备份→桌面便签”中开启，默认关闭。Windows登记当前用户启动项，Linux登记桌面会话启动项，不需要安装系统服务。启动后不打开浏览器，“启动时显示桌面入口”独立决定是否显示右下角箭头；关闭浏览器或便签不会停止服务。系统中额外禁用启动项（例如Windows任务管理器）后，需在系统设置中重新允许。

启动项固定当前程序和数据目录的绝对路径；移动程序或迁移数据后，在新位置运行程序并点击“修复自启动”。状态从本机实际登记读取，不随数据库备份恢复到其他电脑。一个系统用户维护一个ProjNote启动项，修复会切换到当前工作空间。关闭自启动只取消下次登录启动，不结束当前服务。Linux程序所在路径不能包含`%`或`=`；数据目录可以包含百分号、空格和中文。Windows启动命令受系统260个UTF-16字符长度限制，超长时会提示缩短路径。

Linux原生便签依赖Python3、PyGObject/GTK3及可访问的X11/XWayland；缺少依赖会提示错误。Windows使用Win32原生控件；终端维护可使用`dist/ProjNote-cli.exe`，参数与桌面版相同。正式Windows环境仍需实机验证。

## 日常使用

1. **项目与任务**：创建项目后，点击项目名称或“任务计划”进入；任务计划、进度视图、计划版本、需求管理共用项目内标签，面包屑可返回项目列表，刷新和返回保留项目。左侧不再单列WBS和进度。在项目详情维护“项目成员”，可新增姓名或加入已有人员，单机模式也能使用。负责人及相关人员从名单选择；不在名单中时先新增，历史署名保留。同名人员以ID区分；任务负责人选择与局域网分配双向同步，完成或取消的任务不能新改派。再维护WBS、计划日期和进度；子任务决定父任务汇总。可导入`.xlsx`计划，先预览再整批确认；也可在看板、甘特、日历中查看同一份任务。
2. **桌面便签**：添加备忘仍写入所选项目的任务及今日待办，工作记录保存可整理为日志的内容，名称调整不改变原数据。分“添加备忘”、“工作记录”两种模式。任务必须选项目，第一非空行作为标题，全文保留为详情，负责人为当前操作人，计划日期为本地今天；速记可未归类。正文、项目和模式自动保存为草稿，再次打开时自动加载；不再提供手动“恢复草稿”按钮。读取失败时可用“刷新任务”重新连接，保留当前输入。业务保存成功后才清正文。今日任务中选择可写叶子任务后点击“完成选中”，完成项从待办移除；任务历史仍可在完整工作台查看，父任务自动汇总，不提供一键批量完成。面板只显示实际程序版本；作者和公司信息在网页“设置与备份→关于”。
3. **工作记录**：支持中文正文、标签、项目归类及PNG/JPEG/GIF图片。单图最多20MB、4000万像素，每条最多9图；保留原字节并生成缩略图。`#标签`和唯一匹配的`@项目名`可解析，原文保留。记录内容和网页简洁版速记使用Enter换行、Ctrl+Enter（或⌘+Enter）保存，中文输入法选词时不会触发保存；补全可点击或按Tab选择。
4. **工作日志**：一个入口包含个人日志、项目日志、会议纪要、导出中心四个标签。个人日/周/月报按当前操作人筛选任务、问题和工时；项目日报按人汇总当天条目及工时。生成模板的空计划保持空白，不加入“待补充”或范围解释文字；计划可手写，也可手动选取任务/记录追加。保存同范围、同周期的已有日志时，可选择覆盖、不覆盖或输入新标题另存；另存保留原稿，标题最多200字。覆盖须核对现有版本，其他窗口修改后提示冲突，不自动覆盖；重新生成也不会替换已保存正文。
5. **会议纪要**：填写标题、会议日期和Markdown正文；项目、地点、参会人可选；关联项目后从成员名单勾选参会人，原有参会文字保留。保存后可查询历史、搜索、导出或回收恢复；关闭/归档项目的纪要只读。
6. **计划版本与需求**：进入具体项目后切换对应标签。计划版本显式保存完整项目任务树，可查看、下载JSON或比较两版/与当前计划比较，旧版只读。需求可记录描述、验收准则、负责人和来源，关联同项目任务；每次修改填写变更说明，保存后留独立历史版本。覆盖检查列出未关联任务的需求、未关联需求的叶子任务及待核对验收项；任务详情可反查关联需求。验收需填写说明，任务完成不会自动验收需求。
7. **工时与问题**：界面按小时与分钟填写工时，底层换算为整数分钟独立登记，同一人员同一天跨项目合计不超过1440分钟，超过8小时提示核对。问题按状态流转，关闭须填写根因、解决方案和验证结果；已完成叶子任务可填写原因明确重开。

在“任务提醒”中选择有效项目内尚未完成的叶子任务并设置时间，任务选项仅显示名称与负责人，不拼接WBS序号。提醒日期、小时与分钟分开选择，按本地时区保存。每个任务至多一个有效提醒，可调整时间或结束提醒。Windows到时弹出任务消息窗口，20秒自动收起；Linux通过`notify-send`发送桌面系统通知，需要可用的桌面通知服务。程序须保持后台运行，退出后不发送；再次运行会补发仍未完成、尚未通知的到期任务。任务完成、取消或改为汇总任务后自动结束原提醒，重开后需重新设置；项目关闭/归档后暂停发送。结束提醒不会完成任务，发送成功的同次提醒不重复，没有重复规则。网页不再新增自由提醒事项或通过记录语法设置提醒，旧提醒数据保留。

网页`Alt+N`速记、`Ctrl+K`搜索只在应用页面有焦点时有效，不提供系统全局热键。

任务行内修改只在点击“保存”后写入，失焦、选择下拉选项或普通Enter都不会提交；可以取消放弃编辑。点击“移动任务”才显示拖动手柄，拖动只预填位置，点击“保存移动”才生效；退出移动后手柄隐藏且行对齐保持不变。

旧版本保存返回409时，先比较当前数据再决定如何处理；输入和草稿保留，不自动覆盖。网页草稿按数据集隔离在本浏览器保存；原生草稿存数据库，可随完整备份迁移。回收站仅支持恢复，没有永久清理。

## 导出

已保存的个人日志、项目日报、会议纪要、问题、当前需求、需求历史修订、计划版本及计划比较结果可导出Word、Markdown、JSON、Excel或HTML打印稿。计划比较导出冻结两端完整计划，当前计划变化时须重新比较后再导出。会议纪要导出包含标题、日期、项目、地点、参会人和正文；Word默认沿用内置日志模板。

可下载内置Word模板或上传不超过8MB的`.docx`；支持有限的段落占位符、拆run字段及表格循环，无法支持的对象会明确拒绝。Excel为固定三表：工作报告、来源明细、来源快照。HTML成功后可打开打印页，由用户点击打印或使用浏览器另存PDF；没有后台PDF生成。

每个导出任务保留来源版本、冻结内容、模板哈希和结果SHA-256。结果缺失或校验不符会失效。终态任务可“原快照重导”，保持原内容和模板哈希，创建新任务；要导出最新内容则重新选择来源。导出中心的“生成文件维护”先预览和勾选，再确认清理；只删除生成文件，保留业务来源、导出任务和冻结快照。**完整备份不包含`exports/`生成文件**，重要成品请另行下载保存。Office/WPS、真实单位模板和实际打印效果需在目标环境核对。

## 局域网协同

1. 负责人打开本机完整工作台，在“设置与备份→局域网协同”开启服务，默认HTTPS端口为18680。实际地址、证书指纹和下载入口均在该区域；本机负责人端口仍独立。也可使用`./dist/ProjNote --data-dir ./data --lan --lan-port 18680`明确开启。已保存的启用状态会在下次启动恢复；新数据目录默认关闭。
2. 将服务公开证书导入成员设备的受信任证书列表，核对设置页的SHA-256指纹，再访问显示的HTTPS局域网地址。需要时在负责人机器防火墙中允许该端口；程序不会自动修改系统防火墙。不要跳过浏览器的证书校验。
3. 负责人从项目成员名单选择人员、所属项目和可更新的未完成叶子任务，生成10分钟有效、一次性使用的配对码。“复制配对码”在当前弹窗中直接反馈成功或失败。成员在协同网页输入配对码后接入；选择稳定成员ID才会授权，旧自由姓名不会自动授予权限。
4. 成员可查看所属项目完整任务进展和甘特图，只能修改指定任务的进度/允许状态，填写本人按项目、日期的工作日志及小时、分钟工时。不能访问设置、备份、他人日志、导出、工作记录或其他管理接口。任务完成后由负责人明确重开。
5. 负责人可查看收到的成员日报；所选项目、日期的只读汇总每30秒刷新，点击整理进入项目日志页，核对后保存。成员后续修改不会覆盖已保存的项目日志；重新生成会保留来源ID和版本供核对。

会话最长7天；服务重启、关闭后重开、撤销、成员项目或任务归属变更及恢复/迁移均要求重新配对。退出只结束当前成员会话。成员浏览器草稿按数据集、成员、项目和日期隔离；断网后保留输入，重连后手动核对再提交，旧版本冲突不自动覆盖。

LAN为独立IPv4 HTTPS监听，共用负责人机器的单个数据库；成员设备不安装数据库、不共享`app.db`。证书与私钥保存在`data/lan/`，完整备份不包含它们。地址变化导致证书不适用时，先停止协同，再点击“重新生成证书”，成员重新信任并配对。负责人机器必须保持运行。目标Windows设备、真实局域网及证书部署仍需实机核对。

## 备份、恢复与迁移

设置页可创建、下载完整ZIP，包含一致数据库快照、附件、模板和逐文件哈希清单。默认每日自动备份，最多保留30个普通包；可设置2～365份及容量预算，新包校验成功后才清旧包，升级/恢复/迁移保护包保留。建议将完整包另存一份到其他介质。

恢复与迁移须先停服，在终端执行；设置页向导只生成维护步骤。

```bash
./dist/ProjNote --verify-backup /path/to/backup.zip
./dist/ProjNote --data-dir ./data --stop
./dist/ProjNote --data-dir ./data --restore /path/to/backup.zip
./dist/ProjNote --data-dir ./data

# 迁移到新的空目录，原目录保留
./dist/ProjNote --data-dir /path/to/current --relocate /path/to/new-empty-directory
```

恢复前校验清单、哈希、数据库、审计及图片引用；有现存数据库时先创建完整回滚包。若损坏数据无法生成回滚点，保留原目录并停止恢复，可另用新空目录恢复。运行中不要只复制`app.db`，使用完整备份或停服后整体复制。

schema1～9升级到10前会创建并校验受保护的完整旧版包，再事务迁移；schema10增加项目成员任务ID、日志另存字段与任务提醒表，完整备份包含这些业务数据。旧程序不能直接读取schema10，降级需使用对应升级前快照。恢复到新目录后，缺失的导出成品会标为失败，冻结来源和模板仍保留，可按原快照重新生成。LAN成员及其业务数据会恢复，会话和配对失效；新目录启用协同时生成新的证书，成员须重新信任。

## 构建与测试

开发基线为Go1.24、Node24，具体前端依赖以`web/package-lock.json`为准。前端构建结果内嵌进Go程序，普通工作台运行无需Node或外部服务器。

```bash
make web       # 安装前端依赖、类型检查、构建、复制内嵌资源
make build     # 当前平台二进制，无CGO
make windows   # Windows x64桌面版，无控制台
make windows-cli # Windows x64终端维护版
make test      # Go tests与vet
npm --prefix web run test:drafts
npm --prefix web run test:progress
npm --prefix web run test:next-plan
npm --prefix web run test:input-tasks
npm --prefix web run test:log-save
npm --prefix web run test:people-lan
npm --prefix web run test:task-reminders
npm --prefix web run test:project-workflow
npm --prefix web run test:project-navigation

# Linux下在临时用户配置目录验证自启动登记与任务完成
python3 scripts/smoke_startup.py ./dist/ProjNote
# 在临时目录验证扩展功能和两名HTTPS成员
python3 scripts/smoke_extensions.py ./dist/ProjNote
python3 scripts/smoke_lan.py ./dist/ProjNote
# 明确启用真实GTK窗口测试，需可用图形会话
PROJNOTE_TEST_COMPACT_NATIVE=1 go test -race ./internal/platform
```

已有依赖缓存可用`make web NPM_FLAGS=--offline`；指定Go路径可用`make GO=/absolute/path/to/go build`。自动化覆盖不能替代Windows实机、Office/WPS或实际项目使用。
