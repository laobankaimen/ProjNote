# 局域网协同最小设计

当前实现：**v0.6.0-dev / schema10**。默认单用户、本地存储；只有负责人明确开启后才监听局域网。此设计描述已实现的最小协同范围，使用入口见[README](../README.md)。

## 1. 部署与角色

负责人机器运行唯一Go服务和SQLite数据库，持有数据目录锁。原生便签和完整工作台仍使用独立的`127.0.0.1` HTTP端口；协同开启后增加IPv4 HTTPS监听，默认`0.0.0.0:18680`，可配置端口1024～65436。成员设备只需浏览器，不共享数据库文件、不运行第二个可写副本。

负责人是有本机工作台及数据目录访问权的本机用户，不新增远程管理员登录。成员使用稳定身份和受限会话，不建设可配置ACL、多租户或审批引擎。操作系统本机账户与数据目录权限是负责人管理边界；LAN监听从不暴露负责人路由。

| 资源/操作 | 本机负责人 | 局域网成员 |
|---|---|---|
| 项目、计划、需求、任务名称/层级/负责人/日期 | 维护全部 | 只读所属项目的当前任务进展 |
| 指定任务进度 | 维护，执行已有领域规则 | 只能改明确分配给自己的可写叶子任务，带version |
| 每日工作与工时 | 查看收到的成员日报；单机代填仍走原入口 | 只读写本人在所属项目、日期的日报与小时/分钟工时 |
| 项目日报、会议纪要、原始团队来源 | 生成、编辑、保存 | 不开放他人日报或团队来源 |
| 设置、成员、配对、证书、备份、恢复、退出服务 | 本机维护；恢复/迁移须停服 | 不开放 |
| 记录、附件、搜索、历史、回收站、需求、计划快照、导出 | 原有本机功能 | 最小协同版不开放 |

任务投影只包含ID、WBS、名称、负责人显示、计划日期、状态、进度、层级和版本等必要字段，不附带任务私密说明、他人工时或业务快照。HTTPS中的任何hash均进入成员工作台，服务端仍独立执行白名单和对象授权。

## 2. 数据与稳定归属

schema9引入以下六张表，schema10将其同时用作本机项目成员库，并为tasks增加assignee_member_id，已有授权按稳定ID回填；旧快照、审计与任务版本不重写：

| 表 | 权威信息 |
|---|---|
| lan_members | 稳定member_id、显示名、启用状态、auth_version、并发version |
| lan_member_projects | 成员可查看及提交日报的项目范围 |
| lan_member_tasks | 每个任务至多一个LAN成员的独占分配 |
| lan_pairings | 配对码摘要、成员与身份版本、到期时间 |
| lan_sessions | 会话摘要、成员与身份版本、设备说明、到期时间 |
| lan_daily_entries | 成员ID及提交时姓名、项目/业务日、正文/计划/阻碍、分钟、version |

负责人在项目详情维护“项目成员”，可新增人员或选择已有稳定ID加入，单机模式不必先开启LAN。任务负责人、LAN分配及其他人员选择共用项目名单；未列入的人先新增，避免自由输入产生错字。同名成员独立，并显示ID以区分；项目经理、问题负责人、工时署名等旧文本字段采用名单显示名，仍不据此授权。

任务新增/编辑/批量使用assignee_member_id，在同一事务校验有效项目成员并同步当前显示名和lan_member_tasks；从LAN成员设置改任务也同步任务负责人。只允许新指派todo/doing叶子任务，done/canceled不能新增或换人，已有历史姓名与ID保留；父任务不新增成员指派。旧assignee、operator、person_name不自动映射权限，显式修改旧自由署名会撤销原绑定。移出项目须先改派或清空未完成任务的负责人；成功退出撤销项目范围和任务权限，保留已结束任务与日报历史。

创建/修改成员、日报和任务在同一事务校验当前状态、项目范围、稳定归属、字段白名单及version，并写审计。成员写入审计包含稳定ID和实际显示名；不使用本机operator冒充真实提交者。关闭/归档项目不可提交，父任务/已完成任务不可由成员直接改写，完成后重开由负责人操作。

## 3. HTTPS与生命周期

首次开启生成ECDSA P-256自签证书，TLS最低1.2，证书包含当时本机IPv4地址、loopback和localhost，有效期3年。公开证书`lan/server.crt`供本机负责人下载，私钥`lan/server.key`以受限文件权限保存；接口不提供私钥下载。

设置显示实际可访问地址、证书SHA-256指纹和有效期。成员先由可信方式取得公开证书，核对指纹并在设备上建立信任，再访问HTTPS地址；不以忽略校验作为部署步骤。程序不自动安装证书或修改防火墙。

启用状态、端口保存在设置中，下次启动尝试恢复。端口冲突或证书不适用时，本机服务继续运行，协同状态显示错误；不会静默改端口或替换服务身份。变更端口时先确认新监听成功，再关闭旧监听。关闭协同会中止成员连接并撤销配对/会话，本机服务不受影响。

证书过期或网络地址变化后，应先停止协同，再在本机设置明确重新生成证书。旧证书信任失效，成员重新信任、配对。证书和私钥不在完整备份内，新目录恢复后生成新身份；同目录恢复保留本地现有证书，仍清除旧会话。

## 4. 配对与会话

1. 负责人选择启用成员并带当前version生成256位随机配对码，10分钟有效；明文只在本次响应显示，数据库仅存SHA-256摘要。“复制配对码”在当前弹窗显示成功/失败反馈，并改变按钮状态。
2. 成员在受信任HTTPS页面填写配对码和可选设备名称，服务器在事务内消费配对码；重放、过期或身份版本不符均拒绝。
3. 成功后设置256位会话Cookie，最长7天，远端使用HttpOnly、Secure、SameSite=Strict。响应正文不返回会话令牌。
4. 每次请求检查会话期限、成员启用状态和auth_version；范围不由客户端声明。成员退出只撤销当前会话，负责人“撤销配对”撤销该成员全部设备。

服务实际启动/重启、关闭再开启、成员姓名、项目/任务范围或启用状态修改、撤销、重建证书、恢复或迁移均要求重新配对。不能把7天有效期理解为跨服务重启仍保留登录。配对码、会话令牌及其摘要不写入业务审计或普通应用日志，不放URL。

## 5. 接口边界

LAN处理器仅接受TLS、合法Host和完全同源的Origin；拒绝跨站写入。写请求需`X-ProjNote-Request: 1`。身份相关响应`Cache-Control: no-store`，静态页面使用CSP与禁止嵌入策略。LAN handler不回退到本机通用API。

| 通道 | 路由 | 规则 |
|---|---|---|
| 成员公开 | `GET /api/health`、必要静态资源 | 仅最小存活/模式/版本信息 |
| 成员配对 | `POST /api/lan/pair` | 有效一次码，返回Cookie |
| 成员身份 | `GET /api/lan/session`、`POST /api/lan/logout` | 当前会话 |
| 成员工作台 | `GET /api/lan/workspace` | 当前成员的完整授权项目任务投影 |
| 成员日报 | `GET/POST /api/lan/my-daily` | 强制本人；POST白名单及唯一键/version |
| 成员进度 | `PATCH /api/lan/tasks/{id}` | 仅version/progress/status，当前稳定任务绑定 |
| 本机负责人 | `/api/lan/status`、`control`、`members`、`daily-entries`、`certificate`及明确子动作 | 原有本机Host/Origin/请求头边界 |
| 本机项目名单 | `/api/projects/{id}/members`及`/{member_id}` | 列表、创建/加入、带version改名或移出；远端不开放 |

其他LAN API统一拒绝，包括知道ID的备份、导出下载、历史、附件和成员管理链接。本机为界面验证可打开`#/team-member`，成员API仍执行会话授权；该HTTP本机测试路径不代替远端HTTPS部署。

## 6. 日报、工时与汇总

成员日报唯一键为member_id+project_id+work_date，包含当天工作、next_plan、blockers、整数分钟。成员界面按“小时+分钟”录入，分钟部分0～59，总投入最多24小时；显示汇总也采用时分，API与存储仍为minutes。分钟可为0，最多1440，同一成员同一天跨项目总计不超过1440；正文/计划/阻碍/分钟不能全部为空。业务日由成员明确选择，服务器验证真实日期，不改成请求到达日。

重复创建同一日期条目返回409；修改带ID/version且不能换成员、项目或日期。重复网络提交不会产生第二条日报或重复工时。当前不提供离线自动重试队列或通用Idempotency-Key；结果不明时先刷新核对，旧version不自动重试覆盖。

成员日报的minutes是独立来源，不自动生成time_entries，也不推算任务实际工时。项目日报分别汇总单机time_entries及LAN minutes各一次；同一实际工作不应由负责人在单机工时中再次登记。LAN工时额度按稳定ID计算，旧自由姓名条目维持单机口径，不假装二者已自动去重或统一。

负责人设置区域每30秒刷新收到的日报及所选项目/日期的只读汇总，不自动保存。整理按钮转入项目日志，负责人明确生成、核对并保存。source_snapshot保留LAN条目ID/version、提交时姓名、稳定成员ID、工时和当前任务；同名人员分组独立。已绑定任务不再按相同姓名重复归入单机人员组。

已保存正文和来源保持冻结；成员修改源条目后，负责人重新生成再确认，旧稿不会被后台覆盖。保存旧来源遇到当前来源变化时409。任务快照代表生成时的当前进度，不冒充任意历史日的真实状态。

## 7. 草稿、恢复与验证边界

成员浏览器草稿按origin/dataset_id/member_id/项目/日期隔离。退出或会话失效清空页面数据，不能显示上一成员的任务及日志；草稿恢复仍需明确操作。断网保留输入，恢复连接后手动核对再提交。不同设备同时修改同一任务或日报时，旧version409，界面保留编辑值供比较。

完整备份包含LAN业务表、成员归属和配置，以及schema10任务负责人ID、日志另存字段与任务提醒。schema1～9升级前先创建并验证受保护的完整旧版包，再事务迁移至10；旧程序不支持schema10。恢复/迁移先撤销所有会话及配对；实际启用监听再次撤销，旧包无法复活已撤销设备。升级前保护包、独占锁、审计链及附件/模板校验继续执行。恢复维护不通过LAN开放。

自动化覆盖两个项目、两名同名成员、一次码与安全Cookie、受信任TLS、跨项目与其他管理API拒绝、任务409、本人日报、负责人汇总冻结、撤销及完整备份恢复后旧会话失效。Linux真实二进制验证双监听和关闭/重启/证书重建；Windows完成交叉构建及GUI/CLI子系统检查，仍需在目标Windows、实际局域网和成员浏览器验证证书部署、连通性及使用体验。
