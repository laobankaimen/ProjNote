# 局域网协同最小设计

状态：**后置独立设计，尚未实现，不自动开始开发**。当前v0.4.0/schema8仍只监听本机loopback，没有账号、成员会话或LAN权限。本设计不意味着当前程序会监听 `0.0.0.0`，也不把自由填写的负责人/署名当作登录身份。

## 1. 目标和进入条件

一个负责人运行唯一服务和SQLite数据库，维护项目、任务与汇总；成员在所属项目内看完整任务进展，更新自己的任务进度、工作日志和工时。只设负责人、成员两种角色，不建设可配置ACL、跨组织租户或复杂审批引擎。

现有单用户功能已满足当前使用需要，是否进入LAN由实际协作需求另行决定，本设计不触发开发。若未来实施，需保持保存/失败保留、版本冲突、日志来源和独立备份恢复能力；Windows实机、Office/WPS与容量仍按目标环境验证。真正开放LAN前须通过本设计的授权、会话、数据隔离和恢复测试。

## 2. 最小角色与权限

负责人是本服务的数据管理员；成员归属由负责人维护，不由成员请求体声明。暂不增加项目管理员等第三角色。

| 资源/操作 | 负责人 | 成员 |
|---|---|---|
| 项目创建、成员归属、项目状态和配置 | 维护全部 | 只读自己所属项目的必要信息 |
| 所属项目完整任务树、WBS、当前进度 | 全部可读/维护 | 可读所属项目全部任务进展；其他项目不可读 |
| 任务名称、层级、负责人、计划、估算、重开 | 维护并留痕 | 不可修改 |
| 任务进度 | 按既有领域规则维护 | 只能改分配给自己的有效叶子任务进度，带version；状态由约定规则派生，不获得任意终态/重开权限 |
| 个人日志、个人工时 | 可维护/代填并标实际操作人 | 只读写自己的日志/工时，项目必须属于自己；不改其他人的历史条目 |
| 团队汇总、项目日志、会议纪要及生成来源 | 维护/明确重新汇总 | 最小版不开放原始团队人员记录；项目只读发布摘要可另行约定，不能顺带暴露他人原始日志/工时 |
| 搜索、历史、回收站、计数和导出 | 按角色范围读取 | 结果、分页总量与下载全部沿用上述范围 |
| 成员/令牌管理、模板上传、导入、备份、恢复、迁移、停服 | 负责人维护；高影响维护只在本机停服流程 | 不开放 |

成员被移出项目或任务改派后，后续请求立即失去相关写权限；服务器重新校验归属，不能因为页面仍开着或持有旧版本就继续提交。归档、关闭、已完成内容的领域只读规则与角色规则同时适用。

## 3. 身份、历史与迁移

需要稳定的 `member_id` 和服务端认证主体。昵称、operator、assignee、person_name均是可变化的显示/署名文字，**绝不能据此授权**。同名成员、改名、代填和历史署名必须能区分。

最小模型候选：

- `members`：稳定ID、显示名、角色、启用/撤销状态、身份版本。仅角色为负责人或成员。
- `project_members`：项目ID/成员ID、有效状态与版本；作为成员项目可见范围的权威源。
- 任务的稳定成员归属字段或明确任务分配表；保留现有自由assignee显示值，未绑定旧任务只由负责人维护。
- 日志/工时的所属成员ID，以及实际录入人ID、录入时显示名。代填的所属人和操作人分别保存，审计不能把代填者伪装成真实提交者。个人日志唯一范围包含稳定memberID、项目范围（可跨项目）、周期及归一日期；不能沿用当前单用户仅项目/周期/日期的唯一键。团队当天条目唯一键为projectID+业务日+memberID，同名成员互不冲突，同一成员在多个项目各有条目。
- 保存人员条目、任务分配和工时关联时，在同一事务内校验稳定成员存在/启用、当前项目归属、关联任务项目及分配关系；不能只验证显示名或在事务外缓存一次归属。
- 会话、配对与提交幂等记录。只存需要的凭证摘要/元数据，不把原始访问令牌写进操作日志。

迁移时由负责人明确把旧自由姓名映射到成员ID，遇到同名/无法确认项保留未绑定，不自动按字符串相等赋权限。历史正文、来源快照和审计显示名保留，后续改名不回写历史证据。新增模式须有schema迁移、完整升级前备份和失败回滚测试。

## 4. 服务模式与配对

默认仍为loopback单用户模式；未来LAN必须是独立显式选项，并显示实际监听地址、允许来源和关闭方式。不能仅删除Host/Origin校验或把所有来源放开。LAN服务应先具备明确的HTTPS/证书信任方案，记录测试部署条件；开发用明文链路不能冒充正式可用部署。

首次负责人建立走单一受控路径：服务在数据目录首次初始化时生成一次性本机引导凭据，写入仅数据目录所有者可读的文件；负责人经本机CLI读取后在本机初始化页兑换为唯一owner身份并立即作废引导凭据。LAN监听不得在owner尚未建立时启用。丢失负责人访问时，必须停服、取得数据目录操作权后运行本机恢复命令，先建完整回滚点，再轮换认证密钥/epoch并重新配对；不提供匿名网络“找回负责人”或凭自由姓名重置入口。

本机原生便签通过同一数据目录保护的本机凭据通道获得owner身份，凭据不放URL、stdout或普通日志。`desktop/entry`和`desktop/compact`仅接受该本机owner通道的显式操作，不对普通LAN会话开放；来自loopback本身不构成权限。公开health只返回最小存活/版本状态，不返回runtimeToken或其他可用作控制凭据的值。

由负责人在本机生成短时、一次性的配对请求，成员经负责人确认后取得会话。配对请求绑定预期设备及一次性挑战，负责人和成员核对本服务TLS证书指纹后确认；服务端在事务中一次消费挑战，绑定设备会话。配对需有过期、重放拒绝、尝试速率限制和撤销；二维码/复制内容不能把永久密钥留在URL、Referer、浏览器历史和服务日志。成员不能自行给自己增加项目或升级角色。

会话要支持到期、退出、负责人撤销单设备/全部设备、成员禁用后的立即失效；每请求检查会话与身份版本，不能只在登录时检查一次。浏览器使用HttpOnly/Secure/SameSite会话并配套CSRF令牌/Origin校验；若采用显式令牌请求头，也不能免除来源限制、令牌撤销和页面脚本防护。凭证方案实现前应定稿，不同时维护两套模糊认证路径。

本机原生便签在LAN模式也必须具有明确的负责人会话/本机受控通道，不能仅因请求来自127.0.0.1就绕过身份认证。当前单用户本机协议的无账号前提不能直接复制到LAN。

## 5. 每条路由的服务端授权

为所有业务接口建立公开、负责人、成员三类审查清单；只有最小健康状态、登录/配对及必要静态资源可公开。服务器从会话得出主体和项目范围，不信任请求体中的member_id、role或署名。

1. 列表、完整tree、Today、搜索、历史、候选、统计先限制成员项目/所有权，再计数和分页。任务tree对成员使用最小字段projection：ID/WBS/名称/负责人显示/计划日期/状态/进度等完成项目进展所需字段；不顺带返回他人工时、日志、历史细节或完整来源快照。不能先取全量再在前端隐藏。
2. 单条GET、PATCH、软删除、恢复和批量接口逐个检查对象归属；知道ID、旧链接或上传ID不意味着有权限。跨项目移动、导入和批量操作仍由负责人执行。
3. 成员更新任务时只接受进度字段与version；拒绝夹带assignee、project_id、parent_id、计划日期等字段。授权与版本校验必须在同一事务内基于最新状态完成。
4. 日志、工时、关联任务和附件同时检查项目及所属人；禁止成员通过改project_id、task_id或person_name访问他人数据。
5. 导出创建、状态查询、source_snapshot详情、下载和HTML打印都检查来源权限；失去项目权限后旧成品链接也不可访问。项目汇总快照可能含他人条目，不能只检查表面project_id后对所有成员开放。
6. 设置、模板上传、完整备份下载/校验、迁移/恢复/停服、审计管理和成员管理只供负责人。后台CLI的本机文件访问也要保留明确生命周期，不为LAN增加任意路径接口。

上传尚未关联业务对象的附件先绑定上传主体和受控项目/临时有效期；只有相同主体获准的提交才能关联，不能拿到上传ID就跨人引用。附件按业务引用和可访问项目鉴权，不按可猜文件名或全局去重hash授权。公开静态目录不得绕过附件/导出下载接口。未归类记录与未绑定历史对象默认仅负责人可见；共享附件若被多个对象引用，也需有至少一个当前主体获准的业务引用。导出详情、source_snapshot、下载和print每次重新验证当前身份与来源权限；列表可见不使后续链接永久有效。身份/权限范围内响应采用Cache-Control:no-store，注销或切换成员时清除页面缓存、查询缓存和本地敏感状态，不能显示上个身份的tree、附件、日志或导出详情。

## 6. 并发、提交与汇总

继续单服务事务和乐观version。两个成员或负责人/成员同时修改同一任务时，第二个旧version提交409，保留输入、给出当前值，不自动取得新version重试覆盖。角色或归属改变后，即使版本未变，也先按最新权限拒绝不再允许的写入。

成员提交日志/工时需要稳定的 `submission_id` 或 `Idempotency-Key`，数据库幂等唯一键明确为subjectID+operation+key，另存规范化请求fingerprint。重试同一提交返回同一结果；同一唯一键但fingerprint不同返回409；业务写入、审计和幂等结果同事务，不产生双份日志或工时。幂等有效期由服务端明确配置并至少覆盖客户端允许离线重试期；期内不清除可导致重复业务提交的记录，过期重提需明确提示。业务日按服务端配置的项目/服务时区解释并写入，不能把设备本地时钟或请求到达日偷偷替换成员明确选择的工作日期。负责人生成/保存项目汇总也绑定项目、日期、版本和来源集合，重复网络提交不得创建第二份日报。

团队自动汇总的权威输入固定为projectID+业务日的人员当天条目，按memberID唯一；个人跨项目日/周/月报只是派生输出，不同时作为团队输入再尝试文字去重。负责人可看实时派生团队日报，显示每人latest_submission及source ID/version；它随有效提交刷新但尚未形成已保存编辑稿。负责人保存/编辑后冻结该来源集合，之后源提交变化只标“待更新”，不改已保存正文；显式重新生成后再确认保存。汇总记录真实来源ID/version、实际成员提交/代填者和生成时间；新提交不自动覆盖已编辑的负责人正文。成员修改原日志后，旧汇总仍保留原快照，负责人显式重新生成并确认保存。断网重连只提供待确认重提，不把本地离线文字冒充服务已接收。

工时规则按稳定成员ID+业务日执行1440分钟上限，显示名用于阅读；旧自由姓名条目如何纳入须有明确迁移口径，不允许改名绕过额度。相同time_entry被多种报告引用时仍只计一次。

## 7. 草稿、存储和恢复

浏览器及原生草稿按 `dataset_id/member_id/编辑对象或draft_key/写入方` 隔离。退出/切换成员不能恢复前一成员草稿；共享设备必须区分“尚未提交草稿”和业务事实。服务端草稿按身份及版本保存，不能继续让全体成员竞争同一quick_note行。

负责人机器运行唯一服务并持有本地SQLite；成员通过HTTP接口访问，不共享挂载app.db、不为每个成员同步一份可写数据库。并发写入统一事务、审计和备份冻结口径，保留单实例锁。

完整备份由负责人执行和下载，包含数据、成员/归属及必要配置，附件/模板校验继续适用；导出成品留存规则须明确。恢复后必须轮换服务认证secret并推进独立认证epoch，使恢复前全部会话/配对失效，负责人重新建立访问凭证；不能直接恢复旧包中的会话或撤销状态并使已撤销设备复活。恢复启动若不能确认完成轮换，不开放LAN监听。恢复、迁移和回滚仍在停服维护窗口完成，不增加LAN在线任意覆盖数据库接口。

## 8. 分步开发与独立验收

| 顺序 | 交付 | 必须观察的验收 |
|---|---|---|
| L01 | 身份/归属schema与旧姓名绑定向导，升级保护 | 同名不串人；个人日志与团队条目唯一键按memberID；同一人多项目可分别提交；未绑定对象不给成员权限；改名不改历史；升级失败完整回滚 |
| L02 | 显式LAN模式、HTTPS信任、配对/会话/撤销 | 默认仍loopback；未开启不监听LAN；TLS指纹错误、设备不符、过期或重放配对拒绝；一次消费和owner引导/停服恢复可复现；退出/撤销立即失效 |
| L03 | 两角色逐路由授权，附件/导出/搜索范围 | 成员只看所属项目任务最小projection；他人日志/工时/历史/快照不暴露；上传临时ID、旧下载链接、统计总量、缓存或批量夹带均不能越权 |
| L04 | 自己任务进度、个人日志/工时和身份隔离草稿 | 只改允许字段；不能改他人内容；跨设备409不丢输入；退出/切换身份无草稿串用 |
| L05 | 幂等提交、负责人汇总和来源 | subject+operation+key网络重放只写一次，同键异文409；实时汇总显示latest提交/版本；源变化只标已保存稿待更新 |
| L06 | 单服务备份/恢复、故障与真实小组试用 | 成员不能取备份；独立完整包可恢复；旧secret/epoch/session及已撤销设备不会因旧包恢复复活；断网/双提交/权限撤销有记录 |

至少使用负责人+两名成员、两个项目、同名成员、改派任务、成员移出项目、撤销设备、并发编辑、跨日工时与附件/导出旧链接组成测试矩阵。API自动化之外，记录实际目标浏览器、移动设备、TLS部署和网络中断条件。未通过逐路由越权测试前不把“可连通”写成多人协同完成。

## 9. 与当前产品方向的关系

当前不再继续广泛的GJB后续功能开发。项目计划版本和轻量需求管理已按[主设计](ProjNote-详细设计方案V2.1.md)实现，服务于日常单机管理；二者与LAN没有必须的前后依赖，不自动开启协同阶段。

未来若明确需要LAN，再决定目标设备、部署信任和上述实现范围。当前二进制仍没有身份、权限、配对或LAN监听；用户确认现有功能满足使用需要不等于标准认证结论。
