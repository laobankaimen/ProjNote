# ProjNote 项目管理工作台详细设计方案 V2.1

当前实现基线：**v0.5.1-dev / schema9**。本方案描述当前单机与可选局域网架构、业务规则和交互。数据库结构以`internal/store`顺序迁移为准；本文不保留目标SQL草稿、过程日志或历史验收表。

## 1. 定位与范围

工具面向个人项目负责人，连接现场记录、项目任务、工时、日志、会议决定和问题处理。主要动作在本机完成，断网不影响已有功能；完整网页和原生便签访问同一个本机服务。

| 范围 | 当前能力 |
|---|---|
| 项目与进度 | 项目、完整WBS树、任务编辑/排序/移动/批量/重开，Excel新增导入，看板/甘特/日历，计划版本保存与比较，轻量需求及历史版本 |
| 记录与提醒 | 现场记录、标签、图片、未归类整理、一次提醒 |
| 工作日志 | 个人日/周/月报、按人代填的项目日报、独立会议纪要、计划候选手动追加 |
| 工时 | 独立分钟条目、按日期/项目/任务/人员汇总、叶子与父任务实际工时 |
| 输出与维护 | 中文搜索、历史、草稿、回收恢复，Word/Markdown/JSON/Excel/HTML导出、完整备份和停服恢复迁移 |

默认单用户模式，局域网服务须明确开启；不提供云同步。单机自由人员名称是署名和统计字段，不是身份授权；LAN权限使用稳定成员ID。用户已确认GJB5000B二级的使用目标，并确认现有相关功能满足当前使用需要；不再将广泛的标准适配列为后续开发方向。此确认是产品使用范围的决定，不构成标准认证或完整符合宣称。第11节的计划版本和轻量需求按日常管理需要实现；可选协同规则见第12节。

## 2. 架构与部署

```text
原生便签（GTK3 / Win32） ─┐
浏览器工作台（Vue） ──────┼─ 本机HTTP服务 ─ Store/SQLite
                        │                ├ 附件与模板
                        └─ 导出任务 ──────└ 完整备份
局域网成员浏览器 ─ 可选独立HTTPS/成员白名单 ─ 同一Store
```

Go内嵌前端静态资源，监听`127.0.0.1`。每个数据目录由唯一服务持有文件锁；首选端口占用时顺延，运行地址和实例标识写入`runtime.json`。重复启动验证已有实例，不再创建第二个数据库写服务。

| 代码区域 | 职责 |
|---|---|
| `cmd/projnote` | 参数、单实例、服务与原生入口生命周期、升级保护、CLI维护 |
| `internal/store` | schema迁移、领域约束、事务、版本、审计、搜索和汇总 |
| `internal/server` | 路由、请求边界、附件与导出接入、备份服务 |
| `internal/platform` | 文件锁、平台能力、原生便签与浏览器启动 |
| `internal/files` | 原图、缩略图、元数据、大小/格式/引用校验 |
| `internal/exporter` | 受限Word模板、固定Excel与HTML打印渲染 |
| `internal/backup` | 一致快照、清单校验、受控解包与恢复 |
| `web/src` | 工作台、编辑草稿、冲突比较、分页与视图 |

协同启用时另监听`0.0.0.0:18680`（端口可配置），只提供成员接口；负责人管理端保持loopback。两者共享同一Store和单实例锁。LAN证书与私钥在`lan/`中，不属于可下载静态资源。

数据目录包括`app.db`及运行时WAL、`attachments/<id>/original`、`thumb.png`和`meta.json`、`templates/docx`、`exports`、`backups`、`logs`。`runtime.json`和`app.lock`是运行状态，不是业务来源。原生Linux依赖Python3/PyGObject/GTK3及X11/XWayland；Windows使用Go调用Win32控件。正式Windows环境仍需实机验证。

## 3. 一致性与数据模型

### 3.1 公共规则

SQLite开启foreign_keys、WAL、synchronous=FULL、busy_timeout=5000，单连接。写操作在Store互斥锁和数据库事务内完成，业务变更、搜索索引和审计共同提交；失败完整回滚。备份取得相同写锁后生成一致快照。

业务ID为稳定随机标识，不以名称或数组位置关联。服务器维护created_at/updated_at/version；时间戳统一UTC RFC3339，业务日期保留YYYY-MM-DD并按本地日历解释。记录发生时间occurred_at与录入时间分开。更新、回收和恢复须带当前整数version，旧版本409，不自动取得新版本重试覆盖。

业务实体用deleted_at软回收，普通列表/搜索/统计排除回收项。恢复重新校验项目、父任务、只读状态、工时额度和唯一键。回收不物理清除附件。项目仍有任何关联内容（包括回收内容）时不允许回收，避免孤立来源。

## 4. 项目、任务与工时

### 4.1 项目和只读规则

项目状态为active/paused/closed/archived。归档项目及其受控内容只读。closed不允许新增任务或问题；项目/团队日报和会议纪要按关闭项目只读规则处理，工时不能在关闭项目登记、修改或恢复。具体操作仍执行各领域校验，不能通过改project_id绕过原项目只读。

任务必须关联有效项目，父任务须同项目且无环。兄弟按sort_order排序；移动带源/目标版本快照，重算排序、WBS及汇总同事务。普通删除保持已有稳定编码；明确移动时重新编号。批量最多100项，任一版本或领域规则不满足整批不写。

### 4.2 状态、进度与显示

任务状态todo/doing/done/canceled；done叶子强制100%。父任务进度、状态和估算由有效后代计算，不能手填；工时权重使用估算，缺省权重1，取消项不贡献有效进度。逾期由计划结束早于本地今天且仍todo/doing派生，不写入status。

已完成叶子只能通过带原因的显式重开恢复doing，默认进度0，父任务随之重算。父任务不能手动重开。子树回收须明确cascade和全部子项版本，已完成任务及存在有效工时的任务不能回收。

按项目读取完整任务树，DFS顺序附depth/has_children；筛选时保留祖先路径，不因分页剪断父子。全部项目列表可分页。看板只操作叶子；甘特和日历读取相同任务，不产生另一套进度数据。当前没有任务依赖、自动排程、关键路径或工作历。

### 4.3 工时权威源

单机任务实际工时只来自有效time_entries，不从任务估算、日志正文或日报再累加。LAN成员日报的minutes单独按稳定成员ID/业务日校验跨项目1440分钟上限，在项目日报中与time_entries各计一次；不自动转换为time_entries或推算任务投入。负责人不应为同一实际工作在两种来源重复登记。分钟必须为1～1440整数，项目必选，任务可空；关联任务须为同项目有效叶子，已完成叶子允许补记。按人员+业务日跨项目合计不超过1440分钟，超过480分钟在汇总提示核对，不校验计时区间重叠。

人员缺省为当前操作人，历史已存人员不随设置改名。任务后来成为父项时，历史工时仍保留；父实际工时按自身历史条目加后代条目各计一次，移动后按新树归属汇总。人员是单机统计署名，不承担权限。

### 4.4 Excel新增导入

只接受不超过10MB、5000任务的`.xlsx`；旧`.xls`须另存。不执行公式、宏或外链，公式/合并单元格等不支持内容明确拒绝。解析保留原始行号、key/parent_key、名称、负责人、日期、估算、优先级、状态和进度。

先预览规范化结果、错误和父汇总警告，再用绑定原始rows、文件hash、项目/version及过期时间的令牌确认。确认重验项目可写、版本、日期、层级、重复key和环，一次事务新增；同项目source_hash幂等，不按同名任务覆盖。父行估算/进度等采用汇总规则，不能借导入手填父项。

## 5. 记录、提醒与问题

现场记录支持note/inspection/abnormal/photo/decision/other，正文、标题或图片至少一项。项目可空，后续批量归类带每条version，失败整批回滚。标签支持精确筛选和有效记录去重补全；快捷`#tag`、唯一`@项目`不删除原文，无法匹配时保留普通文字。

原图保留字节和SHA-256，另生成缩略图；PNG/JPEG/GIF单张≤20MB、≤4000万像素，单条≤9图。客户端只提交当前数据集已校验附件ID，不接受任意文件路径或外部URL。回收记录保留原图及引用，恢复和备份校验仍能找到它们。

记录时间线的批量工具常驻标题栏；零选择禁用按钮，选择数量变化不插入新行。窄屏固定两行工具栏。图片查看支持切换与缩放，不把缩略图当原件。记录内容及网页简洁版速记中，普通Enter换行；Ctrl/Meta+Enter明确保存，中文输入法composition期间不触发保存。补全使用Tab或点击，不占用普通Enter。

提醒为一次事件，可独立或关联记录。快捷时间为`!今天/!明天/!周五/!YYYY-MM-DD [HH:mm]`，按本地时区解释；缺省09:00，今天已过则一分钟后，同周五已过则下一周五，非法日期不正规化为另一天。正文不丢失，显式时间可消除歧义。普通编辑省略提醒字段时保留原提醒，不重复创建；独立修改提醒联动记录版本，避免跨入口覆盖。记录回收联动提醒，恢复保留已完成状态。Today不展示关闭/归档项目不可操作提醒；没有系统通知或重复规则。

问题状态主线为open→analyzing→fixing→verifying→closed。允许分析/处理时按规则驳回或回退；closed须有root_cause、solution、verify_result，rejected须有原因。流转、issue_history和审计同事务；closed/rejected普通编辑和回收只读。问题不是自动由任意记录文字推断生成。

## 6. 工作日志与会议纪要

网页“工作日志”固定四个标签：个人日志、项目日志、会议纪要、导出中心。各类保存对象分表，避免共享唯一键或把多人汇总当个人事实。

### 6.1 个人日志

GenerateLog接受date、day/week/month、可选项目和assignee，返回project_id/period_type/log_date/content四字段草稿。日按本地日，周归一周一，月归一月首；范围为起点到下个周期起点，不用固定30天代替自然月。

任务/问题按周期内更新时间及人员字段筛选，展示生成时当前状态；记录按occurred_at及项目归集，不推断个人归属；工时只汇总time_entries。月报不截断前500条来源。生成不保存、不覆盖人工正文，也不提供过去状态回放。worklogs只保存正文和范围，没有原始事实生成快照；导出冻结的是已保存日志。

### 6.2 项目日报与单用户代填

team_daily_entries按项目/业务日/人员分别保存正文、next_plan、blockers和task_ids。操作人仍为实际本机录入者，不能把代填署名冒充登录者或签署者。

ProjectDailyLog汇总当天人员条目、该人已登记工时、当前任务及未填写的当前负责人名单。source_snapshot保存生成范围、来源ID/version、工时和任务快照；说明任务是生成时当前进度，不伪称过去日期的真实历史状态。协同启用后同时读取lan_daily_entries，按稳定成员ID区分同名成员，冻结lan_entries、lan_people及lan_minutes；已绑定LAN成员的任务不再按姓名重复归入单机负责人组。未绑定的单机代填来源保持原口径。负责人编辑后明确保存到project_daily_logs，重新生成不自动覆盖旧正文或源快照。

计划候选由按人分配的未完成叶子任务和当日本机记录构成，可按项目/查询分页。记录仅为手动参考。选中后追加到已有明日/后续计划，不自动建任务、提醒或保存日志；周/月基准可取周期末日。

### 6.3 会议纪要

meeting_minutes独立保存标题、meeting_date、Markdown正文，可关联项目，地点与参会人可空。标题≤500、地点≤500、参会人≤2000、正文≤200000字符；标题、真实日期和正文必填。参会人是文本，当前不绑定成员身份。

普通创建/读取/编辑、版本冲突、历史、搜索和回收恢复沿用公共规则。列表按会议日期倒序，支持项目、关键词、日期范围、未归类和offset分页。搜索覆盖标题、编号、正文、地点、参会人及日期；回收从正常查询排除，恢复重建索引。

关闭/归档项目的纪要不能新增、编辑、回收或恢复，编辑前后项目都校验。当前没有纪要签署、批准后revision、自动结论转任务/问题或会议附件模型；这些不由“可保存Markdown”推定实现。

## 7. 原生便签与草稿

默认启动和普通二启只显示固定在工作区右下角的**26×52逻辑像素单箭头**；不支持拖动，不设展开/收起两种入口样式。箭头点击后隐藏入口并打开原生面板；面板只有`×`关闭控制，点击后隐藏面板、恢复箭头并保留编辑稿。显示器或DPI变化时重新计算右下角可见位置，不覆盖任务栏。

面板通过真实本机API取得项目、Today、设置和版本。任务/速记两模式保留同一正文；任务必须选项目，首个非空行trim后作标题（原生最多500字符）、全文作description，负责人取当前operator，计划起止为本地今天。首次空稿恰一个可写项目时才自动选择，不自动建项目。保存真实任务成功后重取Today；速记仍保存records，可未归类。今日任务提供单选和“完成选中”动作，按显示版本提交done/100%，成功后重新读取列表；父任务和关闭/归档项目不可完成，409不自动重试、不清空正在录入的正文。完成项退出待办但保留任务及历史。面板底部提供“打开完整工作台”按钮，并展示真实程序版本；作者/公司信息放网页关于。

原生desktop_drafts是单个quick_note，约1秒防抖保存正文/项目/mode；新空稿task，历史record不误改模式。PUT省略mode保留现值。保存先确认草稿版本，再提交业务对象，最后按已知version清稿；失败/409保留输入。业务已成功而清稿失败时提示不要重复提交，网络结果不明先核对已有对象，当前没有通用自动幂等重提。

不再提供手动“恢复草稿”按钮，首次读取自动加载；刷新任务同时安全重连草稿，未保存的本地输入不能被远端稿静默替换。真实草稿冲突时仍可将当前正文保存为业务记录/任务，保留另一入口草稿。

默认图形启动持续后台运行。Linux父启动进程经就绪握手后退出，服务在独立会话中运行，启动结果和错误写日志；`--foreground`用于终端调试。`--no-browser`、`--no-desktop`及维护命令保留前台语义。Windows桌面版使用GUI子系统，维护版保留控制台。关闭便签、浏览器或入口不停止主服务，显式退出服务或CLI `--stop`结束。

主程序持有单个原生实例。entry-only只显示入口，不重读草稿或展开面板；compact明确展开面板；关闭的helper可由拥有方重建。默认不打开浏览器，只有`--browser`或明确完整工作台动作打开。`--no-browser`兼容纯服务，`--no-desktop`只禁止本次自动入口，desktop_default=0不隐式转浏览器。提供当前用户登录后自启动，不安装无人登录系统服务，不注册系统全局热键。

登录自启动独立于desktop_default：由本机设置明确登记/移除，默认不登记。Windows使用HKCU Run的ProjNote值，Linux使用用户XDG配置目录autostart/org.projnote.ProjNote.desktop；只维护本应用入口。命令固定当前可执行文件与数据目录的绝对路径，不拼接shell，不附带--browser/--compact/--no-browser。Windows使用命令行引用并校验260 UTF-16长度，Linux按Desktop Entry两层转义及%%处理字段码。带控制字符路径拒绝登记，Linux程序路径含%或=时明确提示更换位置，数据路径%仍按字面传递；不安全文件或非本应用同名启动项不能覆盖。

GET/PUT /api/system/autostart仅本机负责人可用，PUT只接受enabled布尔值，不接受客户端提供路径。状态读取操作系统登记，显示当前路径是否匹配及修复提示；非数据库设置、不随备份迁移。关闭只移除登记；移动程序或数据目录后须在新实例明确修复。Windows任务管理器的额外禁用仍由系统设置控制，不能将Run登记当作登录后必然运行的承诺。

网页草稿按dataset_id/页面/对象及写入方隔离在localStorage，支持恢复和冲突比较，未提交不算业务事实，也不随数据库备份。原生稿在数据库中，随完整包保存。草稿恢复必须由用户明确确认，不能用另一个数据集或另一个编辑窗口的旧值覆盖。

## 8. 搜索与接口边界

搜索文档由业务事务同步，FTS5 trigram处理较长中文查询，短词用转义LIKE，用户通配符不变成SQL语法。记录和搜索使用复合keyset游标及真实total；任务、纪要等列表使用offset，不把默认页大小当总量。单条历史从audit分页读取before_json/after_json及解析快照；回收对象仍可查历史。

本机HTTP仅接受当前实例Host/Origin，本机写请求须`X-ProjNote-Request: 1`；JSON字段按白名单校验，SQL资源名由固定表映射选择，不能接受任意表名。附件/导出经受控ID读取，不开放数据目录静态下载。原生helper只可发送固定动作，由Go拥有方访问同一个loopback服务；禁代理/重定向，不接受任意URL。

| 资源组 | 当前路由或操作 |
|---|---|
| 项目/任务/记录/问题/个人日志 | `/api/projects`、`tasks`、`records`、`issues`、`worklogs`及带version的单条操作 |
| 特殊任务 | tree、move、batch、reopen、Excel preview/confirm |
| 人员条目/项目日报 | `/api/team-daily-entries`、`project-daily-logs`，独立generate |
| 会议纪要 | `/api/meeting-minutes`及`/{id}`、`/{id}/history`；内部kind为meeting_minutes |
| 计划版本 | `/api/projects/{id}/plan-versions`保存/列表，`/compare?from=版本ID&to=版本ID或current`比较；`/api/plan-versions/{id}`读取及`/download`下载JSON |
| 需求 | `/api/requirements`普通CRUD/历史/回收；`/{id}/revisions`版本列表、`/{n}`读取及`/compare?from=N&to=N`比较 |
| 工时/提醒 | `/api/time-entries`、summary，`/api/reminders`及完成操作 |
| 草稿/原生 | `/api/desktop/draft`、`desktop/entry`、`desktop/compact` |
| 输出/维护 | export-jobs、export-templates、export-storage、backups、trash、search、settings/system |
| 覆盖与反查 | `/api/projects/{id}/requirements/coverage`、`/api/tasks/{id}/requirements` |
| 冻结导出 | `/api/projects/{id}/plan-versions/compare-export`、`/api/export-jobs/{id}/regenerate` |
| 可选LAN | 本机`/api/lan/status/control/members/daily-entries/certificate`；成员HTTPS仅开放`pair/session/logout/workspace/my-daily/tasks/{id}` |

成功为`{"data":...}`，错误为`{"error":{"code":"...","message":"..."}}`；400校验失败、404不存在/已回收、409版本或领域冲突。原生钩子缺失501、依赖/会话失败503；已成功导出结果缺失410并留痕失效。错误不能回退为SPA成功页。

## 9. 导出设计

来源为已保存的worklogs、project_daily_logs、issues、meeting_minutes、requirements、plan_versions，以及指定历史需求修订requirement_revisions和计划比较plan_comparisons。创建任务必须匹配source_version，在事务内冻结服务端原始字段和正文，不能接收客户端伪造source_snapshot。会议导出组合标题、会议编号/日期、项目、可选地点/参会人和正文，字段明细一并保留，Word默认builtin-journal。

| 格式 | 当前渲染规则 |
|---|---|
| docx | 内置日志/问题模板或≤8MB用户模板；有限占位符、同段拆run、页眉页脚、受限单行rows循环 |
| md | 冻结正文文本 |
| json | 冻结完整来源快照 |
| xlsx | 固定“工作报告/来源明细/来源快照”三表；长文拆片不截断，公式样式文字保留文本，数值按数值写入 |
| html | 转义来源文本、A4打印样式、成功后inline打印页；固定同源按钮脚本由用户点击触发打印 |

Word不执行宏，不接受外部关系、嵌入对象、域、文本框、修订/内容控件或未知占位符；ZIP路径/大小/条数受限。模板用稳定ID和hash保存，不覆盖已有同ID内容。没有任意Excel模板、后台PDF或完整Markdown/Word对象兼容。

导出任务queued→running→succeeded/failed，结果≤64MB，记录模板/渲染器hash和结果大小/SHA-256。文件落盘、同步和原子发布后才能完成。状态/下载/print均保留来源版本；下载复验文件和hash，缺失/损坏则failed。启动把中断queued/running明确标失败，缺失的成功结果失效；重试创建新任务，不改旧记录。已有项目日报的source_snapshot保持冻结，个人日志不伪造原始生成事实快照。

计划比较导出在同一事务捕获两端完整快照与差异，客户端带已显示的from/to哈希；端点变化409，不接收客户端自造比较快照。历史需求按固定revision读取原始需求和当时关联任务。终态任务“原快照重导”创建新任务，使用旧source_snapshot和原模板哈希，不读当前业务来源。模板缺失或哈希变化时拒绝静默替换。

生成文件维护先只读预览，按任务更新时间及可选来源筛选成功成品；明确勾选ID/version后逐项清理，最多5000项。只处理受控目录的正常成品，复验路径、大小与哈希，排除链接及运行中任务。清理保留任务及来源快照，将任务标失效并留审计；下载/清理/worker发布共享文件锁，状态提交失败时尝试还原文件。回收站没有永久删除。

## 10. 备份、升级与维护

完整备份在写锁内VACUUM快照，包含数据库、全部附件与模板、逐文件SHA-256清单，不递归备份backups、不包含exports成品，也不包含lan/证书或私钥。默认按日自动备份，普通包保留份数和容量预算可配置；只有新包完整校验成功才清旧普通包，保护升级/恢复/迁移回滚点及最近有效恢复点。

升级schema1～8前创建并校验完整旧版保护包，再在同一事务顺序迁移至9，失败不提交部分DDL。schema8新增计划版本与需求三张表及关联表，schema9新增LAN成员/归属/会话/日报六张表；备份检查必需字段、历史只读触发器、冻结JSON哈希、需求版本连续性，以及数据库integrity、foreign_keys、审计链和图片引用/hash。更高版本拒绝打开，不用猜测性降级改库。

恢复/迁移须停服并取得独占锁。解包拒绝路径逃逸、重复项、清单/大小/hash不符；当前库存在时先建完整回滚包。替换前后状态受控，中断残留应阻断继续启动而非覆盖。损坏库无法生成回滚点时停止恢复并保留原目录；可在新空目录恢复独立完整包。

迁移目标须新空目录，源/目标不能相同或互相包含；原目录保留。网页维护向导只生成可审查CLI，不在线替换数据库。恢复后导出任务与模板仍在，未包含的生成结果失效后可重导；重要成品由用户另行留存。导出成品可明确预览后清理；回收站不提供永久删除。恢复与迁移撤销所有LAN会话/配对，LAN实际启用也再次撤销，旧备份中的已撤销设备不会复活。证书不随包恢复；新目录新证书须成员重新信任。

## 11. 计划版本与轻量需求

入口位于“任务与WBS”内部标签：任务列表、计划版本、需求管理，不新增左侧导航。

### 11.1 项目计划版本

用户填写名称与说明后显式保存当前项目的完整WBS。事务内读取全部有效任务，保存稳定task ID、父子层级、顺序/WBS、名称、计划起止、负责人、估算、优先级和说明，以及保存时的项目字段。保存带项目version，旧页面冲突保留输入；快照代表保存时的当前计划，不声称是此前打开页面时的任务集合。

已保存版本内容和名称均只读，数据库保护禁止修改或删除；任务后续改名、移动、回收、改期，项目改名都不影响旧快照。版本列表分页，详情完整显示任务树，可直接下载JSON或通过导出中心生成Word、Markdown、JSON、Excel、HTML。

比较以稳定task ID匹配两版或版本与当前计划，显示新增、移除，以及名称、层级/顺序、WBS、日期、负责人、估算等字段变化。列表筛选和折叠不影响保存范围。比较只读，不应用旧版覆盖当前任务，不回滚工时、实际进度或完成状态；保存版本不表示已经审批或成为正式基线。

### 11.2 需求与业务版本

需求必须属于项目，保存唯一REQ编号、标题、描述、验收准则、负责人、来源、状态、业务revision、验收说明和变更说明。标题/描述/准则必填，来源可填写外部编号或现有记录、纪要、问题的说明。编号、项目、业务版本由服务端控制，不跨项目迁移需求。

状态为待处理pending、进行中doing、已验收accepted、作废void。每次编辑须填写本次变更说明并匹配并发version，成功后新增独立业务revision和完整字段/关联任务快照。旧版本只读，保留原保存人、时间和内容hash，可查看及比较两版字段和任务关联变化。回收/恢复只改变并发version，不伪造业务修订。

同一需求可关联多个同项目任务，任务也可支持多个需求；稳定ID连接，任务改名/移动不串换关系，历史版本冻结当时的任务信息。已回收旧链接仍可辨认；不允许新增跨项目或已回收任务关联。需求和计划版本阻止非空项目被回收。

任务done不自动验收需求。进入accepted必须明确填写本次验收说明；已验收后修改须显式改回待处理/进行中或作废并填写原因，再产生新版本。关闭/归档项目的需求和计划版本不能新增或修改，历史仍可查看。当前需求及指定历史修订可使用五种通用导出格式，冻结需求版本、验收准则及关联任务信息。

需求内的覆盖检查按当前有效直接关联计算，汇总为全项目，筛选/分页只影响明细。分别展示无有效任务的需求、未直接关联非作废需求的叶子任务、任务全完成待人工验收、已验收但任务未全完成。父关联不自动覆盖后代，取消任务不视为已完成；检查不代替验收。任务详情提供当前需求反查，跳转先保护编辑草稿。

### 11.3 后置边界

需求管理不扩展成测试用例平台、正式审批、配置管理、质量检查、度量或归档系统。

当前维护关注可靠保存、失败输入保留、版本冲突和独立备份恢复。Windows实机、Office/WPS、输入法/DPI/多屏、打印效果与容量/故障条件按实际部署验证；这些验证边界不转化为新的广泛GJB功能清单。

## 12. 可选局域网协同

默认关闭；负责人在本机设置开启并维护成员。负责人继续使用本机工作台和操作系统账户的数据目录权限，不新增远程管理登录或复杂ACL。成员经独立TLS监听访问固定白名单，任何其他API均拒绝；HTTPS前端始终进入成员工作台，修改hash不能进入管理界面。

授权由lan_member_projects与lan_member_tasks的稳定ID决定。旧assignee文字不自动授权；负责人明确改派任务姓名会撤销原LAN绑定。成员只读所属项目任务的最小字段投影，不能读取其他成员日志、附件、历史、导出、设置或备份；只能更新分配给自己的可写叶子任务progress/status/version，日报强制当前成员、有效所属项目及唯一日期。范围和版本在事务内重验。

配对码256位随机、10分钟、一次消费；会话256位随机、最长7天，数据库仅存SHA-256摘要。远端Cookie为HttpOnly/Secure/SameSite=Strict，写请求须同源和指定请求头。退出撤销当前会话；停启服务、scope/名字/启用状态改变、负责人撤销、证书重建及恢复/迁移均失效并需重新配对。

成员日报按成员/项目/日期唯一并使用version，重复创建409，不产生第二条；更新失败保留本地输入，不自动离线重提。成员草稿按dataset_id、成员、项目和日期隔离。负责人收到的日报与只读项目汇总每30秒刷新；正文须负责人明确生成、编辑、保存，保留真实来源ID/version。源变化不覆盖已保存稿。

证书首次启用生成，成员须信任公开证书并核对指纹。私钥仅保存在负责人数据目录；停用协同不影响本机服务。端口冲突保留本机工作台并显示启动错误，网络地址变化不偷偷替换证书，须停止后明确重建并重新部署信任。详细边界及运维见[LAN最小设计](局域网协同最小设计.md)。
