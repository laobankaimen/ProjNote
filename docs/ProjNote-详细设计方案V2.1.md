# ProjNote 项目管理工作台详细设计方案 V2.1

当前实现基线：**v0.3.5-dev / schema7**。本方案描述当前单机架构、业务规则和交互，未来模型单独列出。数据库结构以`internal/store`顺序迁移为准；本文不保留目标SQL草稿、过程日志或历史验收表。

## 1. 定位与范围

工具面向个人项目负责人，连接现场记录、项目任务、工时、日志、会议决定和问题处理。主要动作在本机完成，断网不影响已有功能；完整网页和原生便签访问同一个本机服务。

| 范围 | 当前能力 |
|---|---|
| 项目与进度 | 项目、完整WBS树、任务编辑/排序/移动/批量/重开，Excel新增导入，看板/甘特/日历 |
| 记录与提醒 | 现场记录、标签、图片、未归类整理、一次提醒 |
| 工作日志 | 个人日/周/月报、按人代填的项目日报、独立会议纪要、计划候选手动追加 |
| 工时 | 独立分钟条目、按日期/项目/任务/人员汇总、叶子与父任务实际工时 |
| 输出与维护 | 中文搜索、历史、草稿、回收恢复，Word/Markdown/JSON/Excel/HTML导出、完整备份和停服恢复迁移 |

当前没有成员登录、LAN监听、云同步或手机协同。人员名称是署名和统计字段，不是身份授权。用户已确认GJB5000B二级的使用目标，并确认现有相关功能满足当前使用需要；不再将广泛的标准适配列为后续开发方向。此确认是产品使用范围的决定，不构成标准认证或完整符合宣称。后续只按实际需要考虑第11节的轻量候选功能，现有版本和数据结构保持不变。

## 2. 架构与部署

```text
原生便签（GTK3 / Win32） ─┐
浏览器工作台（Vue） ──────┼─ 本机HTTP服务 ─ Store/SQLite
                        │                ├ 附件与模板
                        └─ 导出任务 ──────└ 完整备份
```

Go内嵌前端静态资源，监听`127.0.0.1`。每个数据目录由唯一服务持有文件锁；首选端口占用时顺延，运行地址和实例标识写入`runtime.json`。重复启动验证已有实例，不再创建第二个数据库写服务。

| 代码区域 | 职责 |
|---|---|
| `cmd/projnote` | 参数、单实例、服务与原生入口生命周期、升级保护、CLI维护 |
| `internal/store` | schema迁移、领域约束、事务、版本、审计、搜索和汇总 |
| `internal/server` | 路由、请求边界、附件与导出接入、备份服务 |
| `internal/platform` | 文件锁、平台能力、原生便签与浏览器启动 |
| `internal/files` | 原图、缩略图、元数据、大小/格式/引用校验 |
| `internal/exporter` | 受限Word模板、固定Excel与HTML打印渲染 |
| `internal/backup` | 一致快照、清单校验、受控解包与恢复 |
| `web/src` | 工作台、编辑草稿、冲突比较、分页与视图 |

数据目录包括`app.db`及运行时WAL、`attachments/<id>/original`、`thumb.png`和`meta.json`、`templates/docx`、`exports`、`backups`、`logs`。`runtime.json`和`app.lock`是运行状态，不是业务来源。原生Linux依赖Python3/PyGObject/GTK3及X11/XWayland；Windows使用Go调用Win32控件。正式Windows环境仍需实机验证。

## 3. 一致性与数据模型

### 3.1 公共规则

SQLite开启foreign_keys、WAL、synchronous=FULL、busy_timeout=5000，单连接。写操作在Store互斥锁和数据库事务内完成，业务变更、搜索索引和审计共同提交；失败完整回滚。备份取得相同写锁后生成一致快照。

业务ID为稳定随机标识，不以名称或数组位置关联。服务器维护created_at/updated_at/version；时间戳统一UTC RFC3339，业务日期保留YYYY-MM-DD并按本地日历解释。记录发生时间occurred_at与录入时间分开。更新、回收和恢复须带当前整数version，旧版本409，不自动取得新版本重试覆盖。

业务实体用deleted_at软回收，普通列表/搜索/统计排除回收项。恢复重新校验项目、父任务、只读状态、工时额度和唯一键。回收不物理清除附件。项目仍有任何关联内容（包括回收内容）时不允许回收，避免孤立来源。

### 3.2 当前持久实体

| 表 | 主要信息与约束 |
|---|---|
| projects | 编号、名称、客户、负责人、阶段、计划日期和状态 |
| tasks | 项目/父任务、WBS、排序、名称、负责人、计划/实际日期、状态、进度、估算 |
| records | 编号、可空项目、类型、标题/正文、地点、发生时间、标签和附件引用 |
| issues / issue_history | 项目、等级、负责人、状态、原因/方案/验证、逐次流转 |
| time_entries | 项目、可空任务、人员、业务日、整数分钟、说明 |
| worklogs | 可空项目、day/week/month、归一日期、人工保存正文；有效范围/周期/日期唯一 |
| team_daily_entries | 项目/日期/人员、正文、后续计划、阻碍及task_ids；有效项目/日期/人员唯一 |
| project_daily_logs | 项目/日期、人工正文和source_snapshot；有效项目/日期唯一 |
| meeting_minutes | MTG编号、可空项目、标题、会议日期、地点、参会人、Markdown正文 |
| reminders | 标题、可空项目/记录、due_at、done_at；记录最多一个有效关联提醒 |
| desktop_drafts | quick_note单稿：正文、项目、task/record模式、version和更新时间 |
| task_imports | 项目、source_hash、rows_hash和创建任务ID集合；项目/来源hash唯一 |
| export_jobs | 状态、格式、来源ID/版本/冻结快照、模板hash、结果名/hash/大小或错误 |
| audit | 操作人、实体、动作、前后JSON及前一条/本条hash |
| search_doc / search_fts | 受控业务搜索文档及FTS5 trigram索引 |
| settings | 操作人、dataset_id、已确认等级、备份策略、桌面启动偏好 |

PRJ/REC/ISS/MTG编号按创建本地日和序列生成。会议编号由服务端生成且不可编辑，会议日期修改和回收恢复不改变编号，回收编号不复用。schema7增加meeting_minutes，不重建旧日志或改写旧导出快照。

审计记录当前settings.operator和服务端时间，hash基于明确JSON封装串联；可发现一般不一致，不提供可信身份、数字签名或外部可信时间，也无法阻止有本机数据库控制权的人重算整链。并发version与业务文档revision是两种概念。

## 4. 项目、任务与工时

### 4.1 项目和只读规则

项目状态为active/paused/closed/archived。归档项目及其受控内容只读。closed不允许新增任务或问题；项目/团队日报和会议纪要按关闭项目只读规则处理，工时不能在关闭项目登记、修改或恢复。具体操作仍执行各领域校验，不能通过改project_id绕过原项目只读。

任务必须关联有效项目，父任务须同项目且无环。兄弟按sort_order排序；移动带源/目标版本快照，重算排序、WBS及汇总同事务。普通删除保持已有稳定编码；明确移动时重新编号。批量最多100项，任一版本或领域规则不满足整批不写。

### 4.2 状态、进度与显示

任务状态todo/doing/done/canceled；done叶子强制100%。父任务进度、状态和估算由有效后代计算，不能手填；工时权重使用估算，缺省权重1，取消项不贡献有效进度。逾期由计划结束早于本地今天且仍todo/doing派生，不写入status。

已完成叶子只能通过带原因的显式重开恢复doing，默认进度0，父任务随之重算。父任务不能手动重开。子树回收须明确cascade和全部子项版本，已完成任务及存在有效工时的任务不能回收。

按项目读取完整任务树，DFS顺序附depth/has_children；筛选时保留祖先路径，不因分页剪断父子。全部项目列表可分页。看板只操作叶子；甘特和日历读取相同任务，不产生另一套进度数据。当前没有任务依赖、自动排程、关键路径或工作历。

### 4.3 工时权威源

实际工时只来自有效time_entries，不从任务估算、日志正文或日报再累加。分钟必须为1～1440整数，项目必选，任务可空；关联任务须为同项目有效叶子，已完成叶子允许补记。按人员+业务日跨项目合计不超过1440分钟，超过480分钟在汇总提示核对，不校验计时区间重叠。

人员缺省为当前操作人，历史已存人员不随设置改名。任务后来成为父项时，历史工时仍保留；父实际工时按自身历史条目加后代条目各计一次，移动后按新树归属汇总。人员是单机统计署名，不承担权限。

### 4.4 Excel新增导入

只接受不超过10MB、5000任务的`.xlsx`；旧`.xls`须另存。不执行公式、宏或外链，公式/合并单元格等不支持内容明确拒绝。解析保留原始行号、key/parent_key、名称、负责人、日期、估算、优先级、状态和进度。

先预览规范化结果、错误和父汇总警告，再用绑定原始rows、文件hash、项目/version及过期时间的令牌确认。确认重验项目可写、版本、日期、层级、重复key和环，一次事务新增；同项目source_hash幂等，不按同名任务覆盖。父行估算/进度等采用汇总规则，不能借导入手填父项。

## 5. 记录、提醒与问题

现场记录支持note/inspection/abnormal/photo/decision/other，正文、标题或图片至少一项。项目可空，后续批量归类带每条version，失败整批回滚。标签支持精确筛选和有效记录去重补全；快捷`#tag`、唯一`@项目`不删除原文，无法匹配时保留普通文字。

原图保留字节和SHA-256，另生成缩略图；PNG/JPEG/GIF单张≤20MB、≤4000万像素，单条≤9图。客户端只提交当前数据集已校验附件ID，不接受任意文件路径或外部URL。回收记录保留原图及引用，恢复和备份校验仍能找到它们。

记录时间线的批量工具常驻标题栏；零选择禁用按钮，选择数量变化不插入新行。窄屏固定两行工具栏。图片查看支持切换与缩放，不把缩略图当原件。

提醒为一次事件，可独立或关联记录。快捷时间为`!今天/!明天/!周五/!YYYY-MM-DD [HH:mm]`，按本地时区解释；缺省09:00，今天已过则一分钟后，同周五已过则下一周五，非法日期不正规化为另一天。正文不丢失，显式时间可消除歧义。普通编辑省略提醒字段时保留原提醒，不重复创建；独立修改提醒联动记录版本，避免跨入口覆盖。记录回收联动提醒，恢复保留已完成状态。Today不展示关闭/归档项目不可操作提醒；没有系统通知或重复规则。

问题状态主线为open→analyzing→fixing→verifying→closed。允许分析/处理时按规则驳回或回退；closed须有root_cause、solution、verify_result，rejected须有原因。流转、issue_history和审计同事务；closed/rejected普通编辑和回收只读。问题不是自动由任意记录文字推断生成。

## 6. 工作日志与会议纪要

网页“工作日志”固定四个标签：个人日志、项目日志、会议纪要、导出中心。各类保存对象分表，避免共享唯一键或把多人汇总当个人事实。

### 6.1 个人日志

GenerateLog接受date、day/week/month、可选项目和assignee，返回project_id/period_type/log_date/content四字段草稿。日按本地日，周归一周一，月归一月首；范围为起点到下个周期起点，不用固定30天代替自然月。

任务/问题按周期内更新时间及人员字段筛选，展示生成时当前状态；记录按occurred_at及项目归集，不推断个人归属；工时只汇总time_entries。月报不截断前500条来源。生成不保存、不覆盖人工正文，也不提供过去状态回放。worklogs只保存正文和范围，没有原始事实生成快照；导出冻结的是已保存日志。

### 6.2 项目日报与单用户代填

team_daily_entries按项目/业务日/人员分别保存正文、next_plan、blockers和task_ids。操作人仍为实际本机录入者，不能把代填署名冒充登录者或签署者。

ProjectDailyLog汇总当天人员条目、该人已登记工时、当前任务及未填写的当前负责人名单。source_snapshot保存生成范围、来源ID/version、工时和任务快照；说明任务是生成时当前进度，不伪称过去日期的真实历史状态。负责人编辑后明确保存到project_daily_logs，重新生成不自动覆盖旧正文或源快照。

计划候选由按人分配的未完成叶子任务和当日本机记录构成，可按项目/查询分页。记录仅为手动参考。选中后追加到已有明日/后续计划，不自动建任务、提醒或保存日志；周/月基准可取周期末日。

### 6.3 会议纪要

meeting_minutes独立保存标题、meeting_date、Markdown正文，可关联项目，地点与参会人可空。标题≤500、地点≤500、参会人≤2000、正文≤200000字符；标题、真实日期和正文必填。参会人是文本，当前不绑定成员身份。

普通创建/读取/编辑、版本冲突、历史、搜索和回收恢复沿用公共规则。列表按会议日期倒序，支持项目、关键词、日期范围、未归类和offset分页。搜索覆盖标题、编号、正文、地点、参会人及日期；回收从正常查询排除，恢复重建索引。

关闭/归档项目的纪要不能新增、编辑、回收或恢复，编辑前后项目都校验。当前没有纪要签署、批准后revision、自动结论转任务/问题或会议附件模型；这些不由“可保存Markdown”推定实现。

## 7. 原生便签与草稿

默认启动和普通二启只显示固定在工作区右下角的**26×52逻辑像素单箭头**；不支持拖动，不设展开/收起两种入口样式。箭头点击后隐藏入口并打开原生面板；面板只有`×`关闭控制，点击后隐藏面板、恢复箭头并保留编辑稿。显示器或DPI变化时重新计算右下角可见位置，不覆盖任务栏。

面板通过真实本机API取得项目、Today、设置和版本。任务/速记两模式保留同一正文；任务必须选项目，首个非空行trim后作标题（原生最多500字符）、全文作description，负责人取当前operator，计划起止为本地今天。首次空稿恰一个可写项目时才自动选择，不自动建项目。保存真实任务成功后重取Today；速记仍保存records，可未归类。面板展示真实程序版本，作者/公司信息放网页关于。

原生desktop_drafts是单个quick_note，约1秒防抖保存正文/项目/mode；新空稿task，历史record不误改模式。PUT省略mode保留现值。保存先确认草稿版本，再提交业务对象，最后按已知version清稿；失败/409保留输入。业务已成功而清稿失败时提示不要重复提交，网络结果不明先核对已有对象，当前没有通用自动幂等重提。

主程序持有单个原生实例。entry-only只显示入口，不重读草稿或展开面板；compact明确展开面板；关闭的helper可由拥有方重建。默认不打开浏览器，只有`--browser`或明确完整工作台动作打开。`--no-browser`兼容纯服务，`--no-desktop`只禁止本次自动入口，desktop_default=0不隐式转浏览器。不安装开机自启，不注册系统全局热键。

网页草稿按dataset_id/页面/对象及写入方隔离在localStorage，支持恢复和冲突比较，未提交不算业务事实，也不随数据库备份。原生稿在数据库中，随完整包保存。草稿恢复必须由用户明确确认，不能用另一个数据集或另一个编辑窗口的旧值覆盖。

## 8. 搜索与接口边界

搜索文档由业务事务同步，FTS5 trigram处理较长中文查询，短词用转义LIKE，用户通配符不变成SQL语法。记录和搜索使用复合keyset游标及真实total；任务、纪要等列表使用offset，不把默认页大小当总量。单条历史从audit分页读取before_json/after_json及解析快照；回收对象仍可查历史。

HTTP仅接受当前实例Host/Origin，本机写请求须`X-ProjNote-Request: 1`；JSON字段按白名单校验，SQL资源名由固定表映射选择，不能接受任意表名。附件/导出经受控ID读取，不开放数据目录静态下载。原生helper只可发送固定动作，由Go拥有方访问同一个loopback服务；禁代理/重定向，不接受任意URL。

| 资源组 | 当前路由或操作 |
|---|---|
| 项目/任务/记录/问题/个人日志 | `/api/projects`、`tasks`、`records`、`issues`、`worklogs`及带version的单条操作 |
| 特殊任务 | tree、move、batch、reopen、Excel preview/confirm |
| 人员条目/项目日报 | `/api/team-daily-entries`、`project-daily-logs`，独立generate |
| 会议纪要 | `/api/meeting-minutes`及`/{id}`、`/{id}/history`；内部kind为meeting_minutes |
| 工时/提醒 | `/api/time-entries`、summary，`/api/reminders`及完成操作 |
| 草稿/原生 | `/api/desktop/draft`、`desktop/entry`、`desktop/compact` |
| 输出/维护 | export-jobs、export-templates、backups、trash、search、settings/system |

成功为`{"data":...}`，错误为`{"error":{"code":"...","message":"..."}}`；400校验失败、404不存在/已回收、409版本或领域冲突。原生钩子缺失501、依赖/会话失败503；已成功导出结果缺失410并留痕失效。错误不能回退为SPA成功页。

## 9. 导出设计

来源为已保存的worklogs、project_daily_logs、issues、meeting_minutes。创建任务必须匹配source_version，在事务内冻结服务端原始字段和正文，不能接收客户端伪造source_snapshot。会议导出组合标题、会议编号/日期、项目、可选地点/参会人和正文，字段明细一并保留，Word默认builtin-journal。

| 格式 | 当前渲染规则 |
|---|---|
| docx | 内置日志/问题模板或≤8MB用户模板；有限占位符、同段拆run、页眉页脚、受限单行rows循环 |
| md | 冻结正文文本 |
| json | 冻结完整来源快照 |
| xlsx | 固定“工作报告/来源明细/来源快照”三表；长文拆片不截断，公式样式文字保留文本，数值按数值写入 |
| html | 转义来源文本、A4打印样式、成功后inline打印页；固定同源按钮脚本由用户点击触发打印 |

Word不执行宏，不接受外部关系、嵌入对象、域、文本框、修订/内容控件或未知占位符；ZIP路径/大小/条数受限。模板用稳定ID和hash保存，不覆盖已有同ID内容。没有任意Excel模板、后台PDF或完整Markdown/Word对象兼容。

导出任务queued→running→succeeded/failed，结果≤64MB，记录模板/渲染器hash和结果大小/SHA-256。文件落盘、同步和原子发布后才能完成。状态/下载/print均保留来源版本；下载复验文件和hash，缺失/损坏则failed。启动把中断queued/running明确标失败，缺失的成功结果失效；重试创建新任务，不改旧记录。已有项目日报的source_snapshot保持冻结，个人日志不伪造原始生成事实快照。

## 10. 备份、升级与维护

完整备份在写锁内VACUUM快照，包含数据库、全部附件与模板、逐文件SHA-256清单，不递归备份backups、不包含exports成品。默认按日自动备份，普通包保留份数和容量预算可配置；只有新包完整校验成功才清旧普通包，保护升级/恢复/迁移回滚点及最近有效恢复点。

升级schema1～6前创建并校验完整旧版保护包，再在同一事务顺序迁移至7，失败不提交部分DDL。schema7新增会议表；备份检查其12个核心字段以及数据库integrity、foreign_keys、审计链和图片引用/hash。更高版本拒绝打开，不用猜测性降级改库。

恢复/迁移须停服并取得独占锁。解包拒绝路径逃逸、重复项、清单/大小/hash不符；当前库存在时先建完整回滚包。替换前后状态受控，中断残留应阻断继续启动而非覆盖。损坏库无法生成回滚点时停止恢复并保留原目录；可在新空目录恢复独立完整包。

迁移目标须新空目录，源/目标不能相同或互相包含；原目录保留。网页维护向导只生成可审查CLI，不在线替换数据库。恢复后导出任务与模板仍在，未包含的生成结果失效后可重导；重要成品由用户另行留存。回收站和导出目前没有永久物理清理或总配额。

## 11. 后续轻量功能：候选设计、尚未开发

现有功能已满足当前使用需要。以下两项仅用于评估实际增量价值，不代表已实现、已安排开发或固定排期。建议优先项目计划版本，再考虑轻量需求管理，两者无强依赖；具体范围由日常需要决定。候选入口放在现有项目或任务页的内部标签，不扩展左侧导航。

### 11.1 项目计划版本

目的：保留某次明确确认的完整WBS计划，避免日常改期后原计划丢失。复用现有任务、Excel导入和甘特视图，首阶段仅提供**保存、查看、比较**，不加入审批流程。

| 设计项 | 候选规则 |
|---|---|
| 明确保存 | 用户点击保存计划版本，填写版本名称和说明；日常任务编辑、导入、移动或改期不自动生成版本或基线 |
| 完整快照 | 一致读取项目完整WBS，保存稳定taskID、名称、parentID、兄弟顺序/WBS、计划起止、负责人和估算；不能只保存当前筛选结果或可见分页 |
| 保留旧版 | 已保存计划内容只读；当前任务改名、移动、回收或改期不改旧快照，旧版仍能独立显示当时层级与字段 |
| 稳定比较 | 以taskID匹配两版或版本与当前计划，分别列新增、移除、移动、改名、改期、负责人和估算变化；不能用名称或WBS编号代替身份 |
| 展示位置 | 项目/任务页内部“计划版本”标签，查看时可复用树或甘特呈现计划日期；清楚区分当前计划与保存版本 |
| 初期边界 | 不应用旧版覆盖当前任务，不回滚工时、实际日期、完成状态或进度；不把命名版本等同于已批准基线 |

后续实施时，保存快照需取得一致来源并记录项目、版本标识、保存人和时间；比较只读，不产生业务变更。当前没有对应持久模型或接口。

### 11.2 轻量需求管理

目的：明确要交付什么、如何验收，以及由哪些任务落实。先保留项目内最少字段和变更版本，不扩展成完整需求工程或测试管理平台。

| 设计项 | 候选规则 |
|---|---|
| 基本字段 | 项目内唯一编号、描述、验收准则、负责人、来源、状态和需求版本；使用稳定需求ID，改名或编号变化不更换身份 |
| 来源 | 可填写外部编号/说明，或明确引用现有记录、会议纪要、问题；不凭正文自动推断已确认需求 |
| 状态 | 提供待确认、执行中、已验收、作废等必要状态，最终枚举随实际需要确定；验收需明确操作及说明 |
| 需求版本 | 保存变更时保留上一版内容及变更说明，能够查看前后差异；业务需求版本与并发version分开，不用普通更新覆盖历史 |
| 任务关联 | 仅允许同项目任务关联，可由多个任务落实一条需求，也允许一个任务支持多条需求；关系有稳定端点，任务移动或改名不使链接串到其他对象 |
| 验收边界 | 任务完成只表示实施进展，不自动将需求标为已验收；需求验收依据其准则另行确认，不因关联任务全部done直接通过 |
| 展示位置 | 现有项目/任务页内部“需求”标签，可查看字段、历史和关联任务；不新增左侧独立导航或审批层级 |

初期不包含复杂追踪矩阵、测试用例平台、配置管理、质量检查、度量或归档模型。当前没有对应持久表、接口或需求验收工作流。

### 11.3 实施选择与保留边界

这两项是产品建议次序，不是必须连续执行的开发计划。可先在实际项目确认计划版本的保存/比较价值，再决定是否增加需求管理；没有必要时不开发，也不自动进入新版本。

[LAN最小设计](局域网协同最小设计.md)继续作为后置独立设计；是否启动另行决定，不以本节文字授权新增成员、网络监听或权限功能。

当前维护仍应关注可靠保存、失败输入保留、版本冲突和独立备份恢复。Windows实机、Office/WPS、输入法/DPI/多屏、打印效果与容量/故障条件按实际部署验证；这些验证边界不转化为新的广泛GJB功能清单。
