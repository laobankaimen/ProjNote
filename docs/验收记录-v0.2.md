# ProjNote v0.2 增量验收记录

日期：2026-11-05。环境：Linux amd64，Go 1.24.0、Node 24.22.0、内置浏览器。用户本轮已确认目标为 **GJB5000B 二级**，该目标已写入设计、计划、首次向导与设置。本记录说明已交付功能和验证边界，不代表标准符合性认证或全部 P0 完成。

## 本轮交付

| 范围 | 实现与限制 |
|---|---|
| WBS 与批量 | 同项目移动、前/后/内部放置、兄弟排序与编码重算；版本快照校验、防环；负责人/状态/日期批量修改在同一事务内完成；已完成叶子填写原因重开为进行中，父进度随之重算 |
| 草稿与冲突 | 项目、任务、记录、问题、日志编辑草稿按dataset与实体隔离；每标签独立副本；保存不清其他标签的草稿；旧版本恢复先比较，409不自动覆盖新库内容 |
| 记录整理与图片 | 未归类筛选、日期/标签筛选、批量归类；标签补全不再扫描全部含图片记录；图片粘贴、左右切换、缩放/还原、键盘操作 |
| 回收站 | 所有实体使用deleted_at软删除，列表/统计/今日/搜索/草稿生成统一排除；恢复需version和关联约束；不物理清理原图、不提供永久删除。非空项目不可回收；父任务cascade仅API，界面暂仅回收叶子 |
| 备份管理 | 默认保留30个普通完整包，可设2～365份及容量预算；新包解包、哈希/数据库/审计/附件引用校验成功后才清旧包；最新有效包与受保护回滚点保留；失败与容量状态持久显示 |
| 升级与迁移 | schema1→2迁移前先生成并验证受保护旧版完整快照；失败不迁移原库。停服CLI迁移至独立空目录，校验完整数据并保留原目录和dataset_id；恢复前回滚点受保护 |
| 维护向导 | 首次确认操作人、展示实际目录；设置页校验目标/备份并生成按平台安全引用的停服CLI步骤，Windows使用PowerShell；网页不会在线替换数据库 |
| 搜索与分页 | 结果分组、高亮、上下选择、回车直达实体详情；记录按发生时间+ID、搜索按搜索文档ID使用游标及页栈；总数不再截断到500。其他列表仍保留offset |

## 保留的限制与下一步

- 维护向导生成可审阅CLI步骤，尚非纯图形执行的目录选择/停服恢复。旧备份历史保留源目录，目标复制当前数据及本次受保护快照。
- 原生拖放代码已实现，共用同一移动校验；本轮浏览器已验“移动”按钮路径，原生拖放在目标浏览器和Windows仍需手工验收。没有以代码存在替代这项操作验收。
- 任务表分页下可能显示局部分支；任务树超大规模/行内自动保存/完整批量与回收UX仍需继续补齐。父任务cascade支持API，界面无整树删除入口。
- 速记`!时间`提醒和完整快捷语法补全、任务/问题完整历史界面、目标性能/容量、Windows原生及缩放矩阵仍未全部验证。键盘快捷键仅网页有焦点时生效。
- 回收站及图片均不自动永久清理；受保护回滚点不参与普通备份份数删除，可能使容量超过预算，界面会提示。
- 浏览器草稿不能替代数据库保存和备份；浏览器隐私模式、存储额度、用户清除浏览器资料、跨浏览器/跨电脑草稿迁移不保证保留。
- 恢复中断时目前阻断启动并保留旧目录，尚未自动完成恢复journal。大数据量/磁盘满/备份中断的全矩阵仍待专项验收。
- v0.3按计划继续工时、报告和模板导出，再按二级目标实现需求追踪、配置/计划版本、质量检查、度量与归档。单位条款/模板适配须结合权威材料与单位检查单，不作自动认证。
